# JARVIS

Голосовий AI-асистент на Python.

Команда **«відкрити ексел»** відкриває Microsoft Excel у локальному режимі
Windows. Також працюють «відкрий ексель», «відкрий Excel» та «запусти ексел».
Шлях визначається автоматично; за потреби задайте `EXCEL_PATH` у `.env`.

## Доступ і збереження даних

Задайте власний випадковий `JARVIS_API_KEY` у `.env`. Вебінтерфейс попросить
ввести цей ключ; він зберігається лише в поточній сесії браузера. REST-клієнти
передають `X-API-Key`. Браузерний WebSocket передає ключ у підпротоколі,
без додавання до URL. Без налаштованого ключа авторизація вимкнена.
`/status` лишається відкритим для перевірки готовності.

Локальний сервер слухає `127.0.0.1`; для іншої адреси використовуйте
`JARVIS_HOST`. Docker-порти також прив'язані до loopback хоста.
Для віддаленого доступу налаштуйте HTTPS/WSS та ключ доступу.

У Docker бази SQLite, завантажені документи, логи й кеш моделей зберігаються
в томі `jarvis_data` (`/app/data`). Локально шляхи лишаються сумісними з
наявними даними; іншу директорію можна задати через `JARVIS_DATA_DIR`.
Наявні локальні SQLite-бази автоматично в Docker-том не переносяться.
`CHROMA_HOST` вмикає віддалену ChromaDB; без цієї змінної RAG працює з
локальним каталогом `jarvis_vector_db` у директорії даних. Перехід між ними
потребує окремого перенесення або повторної індексації документів.
Перед запуском із наявним томом Chroma перевірте сумісність його версії
та зробіть резервну копію; серверний Compose фіксує Chroma 0.5.23.

Серверний Docker-образ збирає React-інтерфейс і встановлює залежності з
`pyproject.toml`. Мікрофон і локальне відтворення звуку вимкнені;
`/transcribe` обробляє аудіофайли через Whisper. Ollama за замовчуванням
працює на CPU; GPU можна додати в Compose відповідно до вашого хоста.

## Довіра до навичок

Комплектні навички мають контрольні суми в `core/bundled_skills.json`.
Новий або змінений файл не виконується навіть під час завантаження,
доки користувач явно не скаже `активуй навичку ім'я_файлу.py`.
Це працює для `skills/pending/` та наявних файлів у `skills/`.
Схвалення записується у локальний `skills/.approved.json` для конкретної
версії файлу. Активація означає довіру до коду з правами процесу асистента;
статична перевірка коду не забезпечує ізоляцію.

## Відновлення пам'яті та голосу

Векторні колекції прив'язані до назви моделі ембедингів і розмірності.
Якщо лишилася колекція `smart_memory` від попередньої моделі, асистент
повторно обчислює ембединги з наявних текстів у нову колекцію. ID, тексти
й метадані зберігаються; старі колекції не видаляються. Перенесення
продовжується після переривання без повторної обробки вже скопійованих ID.
Перед першим перенесенням зробіть резервну копію `jarvis_vector_db`.
Стан пам'яті та прогрес перенесення доступні у полі `memory` маршруту `/status`.

Для Edge TTS потрібна версія `>=7.3.1,<8`, що підтримує оновлений протокол
Microsoft. Голос і темп можна задати у `.env`: `VOICE_MODEL=uk-UA-OstapNeural`
та `VOICE_RATE=+30%`. У headless-режимі локальне відтворення вимкнено.

Ключі провайдерів, які раніше потрапили у `.env.example`, потрібно відкликати
в кабінетах провайдерів і замінити в локальному `.env`. Заміна прикладу
не видаляє попередні значення з історії Git.

## 🖥️ Запуск на Windows (GUI + мікрофон)

GUI і мікрофон на Windows завжди запускаються локально через `RUN_JARVIS.bat`.
Docker використовується лише для Ollama та ChromaDB.

```bash
# 1. Створити venv
python -m venv .venv
.venv\Scripts\activate

# 2. Встановити залежності
pip install -r requirements.txt

# 3. Налаштувати змінні середовища
copy .env.example .env

# 4. Запустити інфраструктуру в Docker
docker-compose up -d

# 5. Запустити GUI локально
RUN_JARVIS.bat
```

## 🐳 Запуск у Docker (API режим — без GUI та мікрофону)

Запускає: FastAPI сервер + ChromaDB + Ollama.

### Підготовка

```bash
copy .env.example .env
# Відкрити .env та заповнити API ключі
# Змінити OLLAMA_HOST=http://ollama:11434
```

### Запуск

```bash
docker-compose -f docker-compose.server.yml up -d
```

### Завантажити LLM модель (тільки перший раз)

```bash
docker exec -it jarvis-ollama ollama pull qwen2.5:3b
```

### Зупинка

```bash
docker-compose -f docker-compose.server.yml down
```

### Доступні адреси

| Сервіс | URL |
|--------|-----|
| Jarvis API | http://localhost:8001 |
| WebSocket | ws://localhost:8001/ws |
| ChromaDB | http://localhost:8000 |
| Ollama | http://localhost:11534 |

Хочете, щоб Jarvis розпізнавав **ваш** голос точніше?

```powershell
# 1. Wake-word "Neo" (openWakeWord, ONNX)
cd training\neo_wakeword
python -m venv .venv-train; .venv-train\Scripts\activate
pip install -r requirements-train.txt
python train_neo.py
copy output\neo.onnx ..\..\.venv\Lib\site-packages\openwakeword\resources\models\

# 2. Whisper STT (LoRA fine-tune на власному голосі)
```

## 🧠 Проактивні шари (опційно)

Когнітивні шари **Reflector** (метакогніція: уроки з досвіду) та **Anticipator**
(проактивні пропозиції) увімкнені (`*_ENABLED=1`) і отримують дані під час
виконання планів. Проте їхній **автономний фоновий цикл за замовчуванням
вимкнено** (`*_INTERVAL_SEC=0` = лише вручну / за тригером) — щоб Нео не діяв
несподівано «з коробки» і не витрачав ресурси на періодичне сканування.

Щоб увімкнути автономну проактивність, задайте інтервали (секунди) у `.env`:

```bash
REFLECTOR_INTERVAL_SEC=3600     # рефлексія раз на годину
ANTICIPATOR_INTERVAL_SEC=900    # пропозиції раз на 15 хв
```

Ручний запуск без фонового циклу — через API: `POST /reflection/run`
та `POST /anticipator/scan`. Knowledge Graph вимкнено за замовчуванням
(`KG_ENABLED=0`); увімкнення потребує spaCy-моделі (`pip install -e ".[kg]"`,
далі `python -m spacy download uk_core_news_md`).
